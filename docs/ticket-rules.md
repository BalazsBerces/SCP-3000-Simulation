1. Architecture: follow the spec's architecture: the engine-independent C# simulation core behind one facade, and the Godot presentation layer that only reads from it.
2. Test seam: facade-level tests (scenario -> advance time -> assert on snapshot/events). Run the core tests in Release (dotnet test tests/Scp3008.Core.Tests -c Release --filter FullyQualifiedName~<ClassName>): the generation tests run about 5x faster than in Debug. Also build the Godot project with the console executable in headless mode. Everything must pass.
3. Godot 4.7.2 .NET is NOT on PATH; find it with a glob under %LOCALAPPDATA%\Microsoft\WinGet\Packages\GodotEngine.GodotEngine.Mono*\ (use the *_console.exe).
4. Godot runs: the game's own options (--model-check=..., --capture=... and the rest in game/scripts/DevCapture.cs) go after a separate --, or Godot ignores them and just runs the game. Only the build (--build-solutions --quit) may run --headless. Screenshots, colour checks and anything else that reads rendered pixels need a window, because headless Godot draws nothing and waits forever. Start every Godot run with a time limit (for example Start-Process -PassThru, then WaitForExit(300000) and kill it on timeout); a run that hits the limit is a failure to fix, not something to wait for. The runner kills any Godot run of yours that is still alive after {GodotRunSeconds} seconds; a Godot that dies that way hung.
5. Any ticket that adds a downloaded model or texture follows docs/model-workflow.md exactly (search, download once, convert, wire in, test, credits); read it before you start and do not invent your own procedure. A script that only inspects a source must never download it again.
