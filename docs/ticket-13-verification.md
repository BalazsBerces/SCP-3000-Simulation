# Ticket 13: Save and load the full world state

Review fixed point: `3b17f740a0bd4d0699c0f18a7f95c993d1deae2a`. Implements issue #14 against spec #1 and every current ADR. The requested spec-review step was skipped.

## Scope and unattended decisions

- The engine-independent facade provides `Save(Stream)` and `Load(Stream)`. Streams remain caller-owned; loading returns a stopped simulation that the presentation host starts after adoption. Saving takes the existing step lock, so the file describes one complete tick boundary, even with the simulation thread running.
- Version 1 is UTF-8 JSON with a `Version` header and explicit world/subsystem state. An incompatible version, missing required fields, malformed JSON or inconsistent Furniture/stock data raises a clear `InvalidDataException`. There was no previous save format to migrate. No dependency was added.
- Saves contain the actual Department cells, Pillar layout, Displays, Landmarks, Points of interest, Furniture, stock, water, Gear, Bands, Villages, stores, Roles, skills, Known maps, chronicle, Villagers, bodies and sandbox Staff. They also include Fog bank ages/lifetimes, wind and its target, runtime random stream states, walking routes and Need targets, deprivation/decision timers, Staff patrol progress, Restock origins and missing Furniture, stock targets/credits, Dry spells and scheduling, ID counters, speed and leftover real time. Loading rebuilds navigation and sight caches from the saved world; it never regenerates the Store from its seed.
- Observer controls offer Save world and Load world file dialogs, starting in Godot's user-data directory. Files use `.scp3008.json`. Saving flushes a unique sibling temporary file before replacing the destination. Loading runs in the background and adopts only a successfully loaded world; failures display a dialog and retain the current world. Host seed/layout/showcase settings and the snapshot interpolator refresh on adoption. The debug panels move down to leave room for the new controls.
- The camera and other presentation settings are not world state. Systems absent at stage 3 are not invented for persistence. Future tickets must extend the save state and continuation tests when adding mutable state, and bump the format version for incompatible changes. No new domain term or surprising architectural trade-off required a glossary entry or ADR.
- Scope reaches the facade, Weather and Villager state, runtime RNG, SimulationHost, Observer time controls, debug-panel placement, facade tests, the existing DevCapture runner and this verification document. No models, props or textures were added or generated. Existing `.claude` files remain excluded from the commit.

- Windowed Godot sandbox and full large-Store checks exited 0 using `--pause --save-load-check=<absolute directory>` (plus `--villager-sandbox` for the sandbox), each with a 300-second process limit. They exercised the actual Observer button and file-selection signals, replacement of an existing save, background load, equivalent restored snapshots, host settings, readable incompatible-version rejection, preservation of the current world after failure and resumed simulation ticks.

Saves may briefly stall the UI and require substantial disk space; compression and asynchronous saving are not added in this ticket.
