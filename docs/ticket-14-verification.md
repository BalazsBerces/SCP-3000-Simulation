# Ticket 14: Village panel and template chronicle

Review fixed point: `4eddea3b10532689b7067a086b51986f9dc04d15`. Implements issue #15 against spec #1, the glossary and all seven ADRs. The requested spec-review step was skipped.

## Scope and unattended decisions

- Village markers are clickable, keyboard-focusable buttons at the wrapped position nearest the camera focus. Clicking the ground within 8 m of a Village also opens its panel. The panel reads snapshots, refreshing population, member names/Roles, stores and Village history four times a second. Close and Escape dismiss it; replacing or loading a world clears selection and old markers. Its scroll area accommodates long histories and populations. It sits below the seed controls and replaces the community summary while open.
- Wall condition, Beliefs and relations have empty sections because those systems are not yet simulated. This ticket adds no construction, knowledge or relations mechanics, dependencies, models, props or textures.
- The existing core-owned, saved string chronicle remains the source of history. `Emit` records major events before notifying subscribers. Village founding and Villager death each have three short story templates, with Store day/time, names, Sector and relevant context filled in. Founding distinguishes a chosen food/water site from a forced settlement; deaths name starvation or thirst and the Village, if any. Routine clock, weather and consumption events remain outside the major-event chronicle.
- Villager names come from a small fixed catalogue indexed by the existing persistent person ID. Names may repeat; IDs still distinguish people. Names are computed and excluded from serialization, so no mutable name state or save-format change is needed. Village names retain their existing numbered form. Template variants rotate with chronicle length, so loading preserves both existing prose and the next variant without a new RNG stream.
- Village history matches the complete numbered Village name in the saved prose, with a word boundary so Village 1 cannot match Village 10. This deliberately retains the existing save format; the code marks the limit with a `shortcut:` comment. Editable Village names or event types needing richer associations should introduce event references. Future tickets adding major domain events must extend the chronicle templates and their facade checks.
- Scope reaches the core event dispatcher, founding path, Villager snapshot names, the existing renderer/HUD, its DevCapture runner, facade tests and glossary. Persistence already saves and loads the chronicle, so its implementation and version remain unchanged. No decision needed a new ADR. Existing `.claude` files remain excluded.
